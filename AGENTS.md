# Инструкции для AI-агентов

Правила для кодирующих агентов, работающих с этим репозиторием.

## Python web-сервисы

- **Один endpoint — один файл.** Не смешивайте несколько HTTP-эндпоинтов в одном модуле без необходимости.
- **Схемы через Pydantic.** Входные и выходные данные описывайте Pydantic-моделями, а не «голыми» dict.
- **Async только где нужно.** Не делайте всё `async` по умолчанию: используйте асинхронность там, где есть реальное ожидание I/O.
- **Django:** не смешивайте ORM-логику с views. Запросы к БД и бизнес-логику выносите из представлений (в services / selectors / managers и т.п.).
- **Flask:** держите blueprints по модулям предметной области, не сваливайте всё приложение в один файл маршрутов.

## Игры

- **Разделяйте game loop, physics и render.** Цикл игры, физика и отрисовка — отдельные слои/модули.
- **Состояние — в одном месте.** Не дублируйте game state по разным системам; один источник правды для состояния.

## Персональные данные

- **Никогда не логируйте без маскирования.** В логах не должно быть полных секретов, токенов, паролей и сырых ПДн.
- **Токены и пароли — только через переменные окружения.** Не хардкодьте секреты в коде, конфигах репозитория или скриптах.
- **В тестах и фикстурах — только синтетика.** Никаких реальных ФИО, телефонов, email и других настоящих персональных данных.

## Общие запреты

- **Не коммитьте `.env`.** Файлы с секретами окружения не должны попадать в git.
- **Не пушьте ключи.** API-ключи, приватные ключи, пароли и токены не выкладывайте в remote.
- **Перед сдачей изменений запускайте линтер.** Не отправляйте код без прогона линтера (если он настроен в проекте).
